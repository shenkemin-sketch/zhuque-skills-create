# 朱雀 AI 适应性改造清单

## 保留

- 先判断任务是否值得做成 Skill。
- 从真实工作流、输入、输出和边界出发，而不是先套模板。
- 同类 Skill 研究与 `keep / adapt / reject / invent` 综合。
- Scaffold、Production、Library、Governed 四档门禁。
- 触发边界、前向测试、输出评测和证据分级。
- Codex 原生目录、初始化器、校验器、发布与回滚纪律。

## 已完成的朱雀 AI 改造

- 项目名、调用名、显示名和所有者统一到朱雀 AI。
- 中文用户默认获得简体中文、自然、直接、可扫读的输出。
- 改造旧 Skill 前必须先列出 `keep / adapt / remove / add`，保护已有价值。
- 把发散需求收束为优先级、最小完整交付和一个明确下一步。
- 以“用 AI 享受工作，降低内耗，快乐生活”为工作原则，减少重复决定和空流程。
- 朱雀 AI 品牌只进入自有或明确指定的输出，不虚构账号、二维码、网站或宣传信息。

## 只保留在法律与研究层

- 上游作者与仓库信息。
- 第三方许可证、原始版权和官方来源。
- 版本比较与先例研究证据。

这些信息不会进入生成 Skill 的运行人格、默认 Prompt 或项目对外品牌。

## 暂不改造

- 不改变 Codex 规定的 `SKILL.md`、`agents/openai.yaml` 等技术合同。
- 不为了品牌统一削弱密钥扫描、发布门禁或证据边界。
- 不增加未经用户提供和核验的朱雀 AI 社交账号、Logo、网站、二维码或案例数据。
